# 박재영 — 직접 해야 할 일만

보고서 문장과 서버 구성은 작성 완료 상태다. 아래 작업은 Windows/VM 화면 캡처, 비밀번호 입력, 재부팅, 본인 확인이 필요해서 직접 해야 한다.

## 1. VMware 포트포워딩 설정·캡처

Windows에서 VMware 가상 네트워크 편집기를 **관리자 권한**으로 열고 NAT 네트워크의 Port Forwarding에 다음 두 규칙을 추가한다.

| 용도 | 프로토콜 | 호스트 포트 | VM IP | VM 포트 |
| ----- | ----- | -----: | ----- | -----: |
| error-dungeon-http | TCP | 8080 | 192.168.232.130 | 80 |
| error-dungeon-ssh | TCP | 2222 | 192.168.232.130 | 22 |

두 규칙이 한 화면에 보이게 캡처하여 **캡처 4-1**에 붙인다. VM IP가 바뀌었다면 Ubuntu에서 `hostname -I`로 확인한 현재 IP를 사용한다.

## 2. Windows hosts 설정·캡처

관리자 PowerShell에서 실행한다.

```powershell
Add-Content C:\Windows\System32\drivers\etc\hosts "127.0.0.1 error-dungeon.local"
ipconfig /flushdns
Get-Content C:\Windows\System32\drivers\etc\hosts | Select-String error-dungeon.local
```

PowerShell 전체 창을 **캡처 7-3**에 붙인다. 기존 `error-dungeon.local` 줄이 이미 있다면 중복 추가하지 말고 그 줄을 `127.0.0.1 error-dungeon.local`로 고친다.

## 3. Ubuntu 터미널 캡처

저장소 루트 `/home/jay-0x50/ErrorDungeon`에서 아래 명령을 하나씩 실행한다. 스크립트가 매 단계 `date`와 `whoami`를 같이 출력한다. 터미널 창과 `jay-0x50@...$` 프롬프트가 모두 보이게 캡처한다.

```bash
chmod +x deploy/scripts/report-evidence.sh
./deploy/scripts/report-evidence.sh 1
./deploy/scripts/report-evidence.sh 2
./deploy/scripts/report-evidence.sh 3
./deploy/scripts/report-evidence.sh 5-code
./deploy/scripts/report-evidence.sh 5-curl
./deploy/scripts/report-evidence.sh 5-tree
./deploy/scripts/report-evidence.sh 6
./deploy/scripts/report-evidence.sh 7
./deploy/scripts/report-evidence.sh 9
```

| 실행 명령 | 붙일 위치 |
| ----- | ----- |
| `1` | 캡처 1-1, 1-2 |
| `2` | 캡처 2-1, 2-2, 2-3 |
| `3` | 캡처 3-1, 3-2 |
| `5-code` | 캡처 5-1(a), 5-1(b) |
| `5-curl` | 캡처 5-2, 5-3 |
| `5-tree` | 캡처 S-3 |
| `6` | 캡처 6-1, 6-2 |
| `7` | 캡처 7-1, 7-2, 7-4 |
| `9` | 캡처 9-1, 9-2 |

출력이 길면 글자가 작아지지 않도록 해당 번호를 `(a)`, `(b)` 두 장으로 나눈다.

## 4. 재부팅 증빙

열어 둔 파일을 저장하고 실행한다.

```bash
sudo reboot
```

VM이 다시 켜지면 저장소로 이동해 실행한다.

```bash
cd /home/jay-0x50/ErrorDungeon
./deploy/scripts/report-evidence.sh 6-reboot
```

`uptime`, `active`, `enabled`가 모두 보이는 터미널 전체 화면을 **캡처 6-3**에 붙인다.

## 5. 브라우저 캡처

Windows Chrome에서 `http://error-dungeon.local:8080`에 접속한다.

1. 주소창, Error Dungeon 게임, `3학년 4반 4번 박재영`, `ONLINE`, 서버 시각, 방문 수가 보이게 전체 화면 캡처 → **S-1, 8-1**.
2. 상단의 **서버 현황**을 눌러 동적 서버 페이지 전체 화면 캡처 → **S-2**.
3. 원래 게임 탭으로 돌아와 F5를 누른 뒤 서버 시각과 방문 수가 달라진 화면 캡처 → **8-2**.

주소창이 잘리거나 학번·이름이 안 보이는 캡처는 사용하지 않는다.

## 6. 가산점 자동 백업 설치·캡처

```bash
cd /home/jay-0x50/ErrorDungeon
sudo ./deploy/scripts/install-backup-cron.sh
sudo /usr/local/sbin/error-dungeon-backup
./deploy/scripts/report-evidence.sh bonus
```

cron 설정, 생성된 `.tar.gz`, 배포·상태 점검 스크립트, 저장 API의 입력→조회 결과가 보이게 나눠 캡처한다. 이 자료로 다음 네 항목을 증명할 수 있다.

- 배포 자동화 스크립트
- crontab 프로젝트 자동 백업
- 서버 상태 점검 스크립트
- 입력 처리·SQLite 데이터 저장

## 7. 제출 직전 본인 확인

- 보고서의 작업 시간과 소감이 실제 경험과 맞는지 읽고 필요한 문장만 본인 말투로 고친다.
- 보고서 윤리 서약과 AI 활용 기록을 읽고, 질문받았을 때 설명할 수 있는지 확인한다.
- 모든 `(여기에 스크린샷...)` 칸에 본인이 직접 찍은 원본 캡처를 붙인다.
- 제출 파일명을 학교 양식에 맞게 `3404 박재영_리눅스배포보고서`로 정한다.
- VM은 시연이 끝날 때까지 삭제하지 않는다.

## 시연 때 외울 핵심 네 문장

1. 브라우저는 8080 포트포워딩을 거쳐 Nginx 80번에만 접속한다.
2. Nginx가 `/api/` 요청만 VM 내부의 FastAPI `127.0.0.1:8080`으로 전달한다.
3. FastAPI는 관리자 권한이 없는 `errordungeon` 계정으로 systemd에서 자동 실행된다.
4. 서버 시각과 방문 수는 FastAPI와 SQLite가 요청마다 만들기 때문에 정적 페이지가 아니다.
