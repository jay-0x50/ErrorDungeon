## 1. 핵심 경험(Experience Pillars)

1. **전투가 핵심**
    - 공격/회피/가드/패링의 **타이밍**과 **기력 관리**가 승패를 좌우.
2. **오픈월드 탐험의 보상**
    - 지형/동선/비밀 구역을 발견 → 장비/재료/스킬/단축로(쇼트컷)로 보상.
3. **보스 중심의 성취**
    - 보스는 “기믹/패턴/페이즈”로 설계, 처치 시 **영구 성장 자원**과 **진행 잠금 해제**.
4. **죽음이 주는 압박 + 회복 가능한 손실**
    - 사망 시 축적 재화(혼/룬 등)를 떨어뜨리고, 회수 전 재사망 시 소실.
5. **빌드 다양성**
    - 무기 타입/속성/스킬 트리 조합으로 플레이 스타일이 바뀜(근접/기력형/방어형/원거리 보조/상태이상).

---

## 2. 기본 게임 루프(상위)

```
[탐험] → [전투/전리품] → [체크포인트(휴식)] → [성장(레벨업/강화)] → [지역 보스] → [새 지역/새 이동수단/새 능력 해금] → 반복
```

세션 목표(플레이 단위):

- 특정 지역의 “중간 목표(서브 보스/던전/퀘스트)” 달성 → 체크포인트 확장 → 장비/레벨 강화 → 메인 보스 도전.

## 3. 플랫폼/기술 및 배포 환경(리눅스 기준)

### 3.1 권장 기술 스택(개발 편의 + 리눅스 서버 운영 안정성)

- **서버**: Ubuntu 24.04 LTS + Nginx(리버스 프록시) + systemd + ufw
- **서버 언어**: Go 또는 Node.js(TypeScript) 또는 Python(FastAPI)
- **DB**: PostgreSQL(권장) 또는 SQLite(단일 서버/개인 프로젝트용)
- **캐시/세션**: Redis(선택)
- **클라이언트**: Unreal Engine 5(권장) 또는 Unity(URP/HDRP)
    - *클라이언트 빌드는 Windows/Linux 지원 목표(서버는 Linux 필수).*

### 3.2 배포 목표(최소)

- 전용 서버 프로세스(게임 룸/월드 상태/매칭) 1개
- DB 1개
- 로그/모니터링: journald + logrotate(최소), Prometheus/Grafana(선택)

### 3.3 보안/운영 체크(필수)

- ufw로 필요한 포트만 오픈(예: 22, 80/443, 게임 포트)
- 서버 권한 분리 계정(예: `gamed`), systemd 서비스 등록 및 재부팅 자동 실행
- 서버 권한 상승 작업은 배포 스크립트로 분리

## 4. 핵심 시스템(소울라이크 필수 기능)

### 4.1 체크포인트(휴식처) 시스템

- 기능
    - HP/기력 회복
    - 물약/소모품 “기본 보충” (디자인에 따라)
    - **리스폰 포인트** 설정
    - (선택) 스킬/장비 세팅 변경
- 트레이드오프
    - 주변 적 리젠(기본)
    - 특정 월드 이벤트 초기화(선택)

### 4.2 사망 페널티(재화 드랍/회수)

- 사망 시: 현재 누적 재화(룬/혼/정수) 드랍
- 드랍 지점: 사망 지점(또는 보스룸 입구)
- 회수 조건: 드랍 지점 도달 + 상호작용(또는 자동 회수)
- 재사망 시: 이전 드랍은 소실, 새 드랍으로 갱신

### 4.3 성장(레벨업)

- 재화(룬/혼)로 레벨업
- 레벨업은 체크포인트에서만 가능(권장)
- 스탯 예시
    - 생명력(HP), 기력(스태미나), 근력/기술(무기 스케일), 집중(스킬 자원), 방어/저항

### 4.4 장비/강화

- 무기 타입(예: 대검/도끼/창/쌍검/카타나/둔기/원거리 보조)
- 방어구(경/중/중량) → 회피 성능/경직 저항/피해 감소에 영향
- 장비 강화
    - 강화 재료(광석/정수 등) + 비용
    - 강화 단계에 따라 공격력/가드 성능/스케일링 개선
- 무게(장비 하중)
    - 구르기(회피) 성능이 하중 구간에 따라 변화(가벼움/보통/무거움)

### 4.5 전투(스태미나 기반)

- 기본 행동
    - 약공격/강공격/차지 공격
    - 가드(스태미나 소모, 가드 브레이크 가능)
    - 회피(무적 프레임, 스태미나 소모)
    - 패링(고난이도, 성공 시 큰 리턴)
    - 스킬(무기전기/인술/마법 등), 아이템 사용
- 상태이상(선택)
    - 출혈/중독/동상/화상 등 축적형
- 다운/경직(선택)
    - 강공격/백스탭/가드 브레이크로 치명타 창 생성

## 5. 월드/오픈월드 구성

### 5.1 월드 구조(권장 설계)

- 메인 지역 3~5개(초기 목표)
- 각 지역 구성
    - 오픈필드(탐험/자원/잡몹/정예몹)
    - 던전 1~3개(밀도 높은 전투/퍼즐/쇼트컷)
    - 보스 1명 이상(메인/서브)
- 이동/해금
    - 지역 진입 조건(열쇠/퀘스트/보스 처치)
    - 쇼트컷(문/엘리베이터/지름길)로 동선 단축

### 5.2 탐험 보상 설계

- “눈에 보이는 목표” + “숨겨진 목표” 동시 제공
    - 지형 힌트(절벽, 동굴, 붕괴한 성벽)
    - 원거리 랜드마크(탑/성/거대 수목)로 방향성 제공
- 보상 종류
    - 강화 재료
    - 신규 무기/방어구
    - 스킬/마법/인술
    - 진행 해금(열쇠, 능력, 이동수단)

## 6. 보스 설계(개발에 바로 쓰는 포맷)

### 6.1 보스 공통 규격

- 보스 상태
    - HP, 강인도(경직 게이지), 페이즈(Phase 1/2/3)
- 패턴 구성
    - 기본 6~10패턴(근/중/원거리 대응)
    - 페이즈 전환 시 2~4패턴 교체/강화
    - 리스크-리턴: 큰 패턴은 확정 빈틈 제공
- 난이도 조절 포인트
    - 텔(예고 동작) 길이
    - 콤보 길이/추적 성능
    - 패턴 간 딜레이(숨 고르기)
    - 가드/패링 가능 여부

### 6.2 보스 시트(템플릿)

| 항목 | 내용 |
| --- | --- |
| 이름 | (예: “무너진 장군, 도윤”) |
| 지역/등장 | (지역명/보스룸 위치/진입 조건) |
| 콘셉트 | (무기/전투 스타일/약점) |
| 페이즈 | P1(기본) / P2(광폭) |
| 핵심 기믹 | (예: 바닥 장판, 소환, 무기 변형) |
| 주요 패턴 | (패턴명: 텔 → 공격 판정 → 회피/대응법) |
| 처치 보상 | (룬/고유 장비/지역 해금/퀘스트 진행) |
| 체크포인트 | (보스룸 전 휴식처 위치) |

## 7. 콘텐츠(초기 MVP 범위 제안)

### 7.1 MVP 목표(“플레이 가능한 소울라이크”)

- 1개 지역(소형 오픈필드) + 1개 던전 + 1개 메인 보스
- 체크포인트/사망페널티/레벨업/장비 강화 최소 구현
- 무기 타입 2종(예: 대검/카타나)
- 적 타입 6종(잡몹 4 + 정예 1 + 보스 1)

### 7.2 확장 1차

- 지역 2~3개로 확장
- 보스 3~5명
- 스킬/마법 계열 1~2개 트리 추가
- NPC/퀘스트(간단) + 상점

## 8. 데이터/모델(초안)

World
- worldId, regionId

## 9. 네트워크(선택: 멀티플레이 고려 시)

### 9.1 범위 정의

- 싱글플레이(기본) + (선택) 협동 2~3인 + (선택) 침입/결투
- 멀티는 “나중에”를 전제로, **서버 권위(Server-authoritative)** 구조를 추천

### 9.2 서버 권위 규칙(최소)

- 플레이어 위치/행동 입력은 서버 검증
- 전투 판정(히트/피해/상태이상)은 서버 확정
- 치트 방지: 클라가 “결과”를 결정하지 못하게 함

## 11. 개발 로드맵(구현 순서)

1. **코어 전투 프로토타입**
    - 이동/카메라/락온/회피/가드/피격/사망
2. **체크포인트 + 사망 페널티**
    - 리스폰, 재화 드랍/회수, 적 리젠
3. **성장/장비**
    - 레벨업, 스탯 반영, 장비 강화
4. **적 AI + 보스 1개**
    - 패턴 시트 기반 구현, 페이즈 전환
5. **월드 구성**
    - 지역 1개 + 던전 1개 + 쇼트컷
6. **리눅스 서버 배포(선택 기능)**
    - 전용 서버/DB/로그/모니터링, systemd, ufw, Nginx(필요 시)

## 12. 열린 질문(기획 확정 전 결정)

- 싱글 중심으로 갈지(권장) / 협동을 넣을지(추후)
- 세계관/아트 방향(동양풍/다크 판타지/폐허 문명 등)
- “스탯/스킬 트리” 복잡도(단순/중간/하드코어)
- 보스 수와 지역 수(과제/일정 기준으로 MVP 스코프 확정)
- 서버를 “필수”로 둘지(멀티/치트 방지) vs “배포 요구사항만 충족하는 최소 서버”(런처/랭킹/세이브 동기화)
