# Story/Cutscene Spec — 스토리·세계관·컷신

## 0. 목표

- 기존 전투/탐험 중심 기획에 서사 축을 추가해, 보스전과 지역 진행에 "왜"를 부여한다.
- 코덱스가 그대로 구현할 수 있도록 컷신 트리거/데이터 스키마 수준까지 정의한다.

> ※ 아래 세계관 톤은 제목("Error Dungeon")과 기존 보스 설정(도윤이 광기로 잠식됨)을 근거로 임시로 잡은 초안입니다. 원하는 톤(동양풍/서양 다크판타지/SF 혼합 등)이 있으면 알려주시면 바로 수정합니다.

## 1. 세계관 한 줄 요약

> 세계를 지탱하던 오래된 결계(체계)에 정체불명의 **"오류"**가 퍼지며, 땅과 사람과 짐승이 뒤틀리기 시작했다. 플레이어는 오류에 완전히 잠식되지 않는 몸을 지닌 채 깨어난 이름 없는 자로, 화톳불(체크포인트)을 다시 지피며 지역마다 퍼진 오류의 근원을 향해 나아간다.

- **오류(Error)**: 세계관 내 부패/타락의 실체. 감염된 존재는 점점 이성을 잃고 폭주하며, 결국 몬스터화된다. 보스는 대개 "한때는 온전했던 존재가 오류에 잠식되어가는 마지막 순간"으로 설계한다.
- **화톳불(체크포인트)**: 오류의 확산을 일시적으로 막는 유일한 안전지대. 플레이어가 화톳불을 밝힐 때마다 주변 오류가 옅어진다는 설정으로, 기존 체크포인트 시스템(휴식/리스폰/적 리젠)과 자연스럽게 연결.
- **사망 페널티(재화 드랍)**의 서사적 이유: 플레이어가 지닌 힘(혼/룬)이 오류에 흡수되었다가, 다시 회수하면 오류를 역으로 정화해 되찾아온다는 설정으로 기존 시스템에 의미 부여.

| 무너진 장군, 도윤 | 1지역 보스 | 폐성을 지키던 장군이었으나 오류에 잠식됨. P2(광폭화)는 마지막 이성이 무너지는 순간을 표현 |

## 3. 전체 스토리 아크(3막 구조, 초안)

| 막 | 지역 범위 | 요약 |
| --- | --- | --- |
| 1막 (도입) | 지역 1(폐성 외곽) | 플레이어 각성 → 오류의 존재 인지 → 도윤과의 대면(첫 좌절 또는 첫 승리) |
| 2막 (전개) | 지역 2~3 | 오류의 근원 단서 추적, 조력자의 정체에 대한 의문, 각 지역 보스가 "오류에 잠식되어가는 방식"의 변주를 보여줌 |
| 3막 (결말) | 최종 지역 | 오류의 근원과 대면, 정화/융화 등 엔딩 분기 |

MVP 스코프(지역 1개 + 보스 1개)에서는 **1막까지만 완성**하고, 2·3막은 확장 로드맵으로 남겨두는 것을 권장.

## 6. 컷신 트리거 시스템(구현 연동)

### 6.1 상태머신 변경 필요사항

Combat Spec 9.1의 상태 목록에 **Cutscene** 상태 추가 필요:

- 우선순위 위치: `Dead` 다음, `HitReact/Knockdown`보다 위 (컷신 중에는 피격/입력 모두 차단)
- 진입 시: 플레이어 입력 잠금, 카메라 제어권을 컷신 시스템으로 이관
- 종료 시: 트리거 발생 직전 상태(Idle/Locomotion 등)로 복귀

Combat Spec 9.2 입력 우선순위표는 아래와 같이 갱신 권장:

1. Dead
2. **Cutscene(스킵 불가 구간)**
3. HitReact/Knockdown
4. Dodge
5. Parry
6. Guard
7. Attack
8. UseItem
9. Locomotion

### 6.2 트리거 종류

- 지역 최초 진입 트리거(월드 볼륨)
- 보스룸 진입 트리거(볼륨)
- 보스 HP 임계치 트리거(Boss Sheet 페이즈 전환 조건과 동일 값 사용)
- 보스 처치 트리거
- 엔딩 트리거(최종 보스 처치)

### 6.3 데이터 스키마 제안 (cutscenes.json, Data Tables 문서 스타일과 통일)

```json
{
  "id": "CS_01_BossIntro_Doyun",
  "triggerType": "bossRoomEnter",
  "bossId": "boss_doyun",
  "skippable": true,
  "durationSec": 15,
  "cameraTrack": "doyun_intro_track_01",
  "dialogueId": "dlg_doyun_intro"
}
```

- `triggerType`: `gameStart` / `regionEnter` / `bossRoomEnter` / `bossHpThreshold` / `bossDeath` / `ending`
- `bossHpThreshold` 타입일 경우 `hpPercent` 필드 추가(Boss Sheet의 페이즈 전환 조건과 동기화)

## 7. 환경 스토리텔링(비컷신)

- 아이템 설명 텍스트, 시체/오브젝트 배치, 벽면 낙서·기록으로 세계관을 보강한다(직접 서술 대신 암시 위주).
- Data Tables 문서의 Item 스키마에 `loreText`(선택) 필드 추가를 권장:

```json
{
  "id": "wp_spear_doyun",
  "name": "도윤의 장창",
  "loreText": "폐성의 마지막 장군이 쥐고 있던 창. 날 끝에는 아직도 번개의 잔향이 남아있다."
}
```

## 8. 대사/텍스트 톤 가이드

- 문장은 짧고 파편적으로, 직접 설명(exposition dump)은 지양하고 암시 위주로 작성한다.
- 보스 대사는 전투 흐름을 방해하지 않도록 전투 시작/페이즈 전환/사망 시점, **총 3회 이하**로 제한한다.
- 조력자 NPC 대사는 퀘스트/이동 동기부여 목적일 때만 사용, 세계관 설명은 아이템 텍스트/환경으로 분산한다.
